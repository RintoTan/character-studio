# 产品愿景与长期演进

> 定位：**长期产品规划**。这里描述「为什么做、往哪走、边界在哪」，不描述「已经做了什么」。
> 当前能力以 [`PROJECT_STATUS.md`](PROJECT_STATUS.md) 与代码为准；排期与状态以
> [`ROADMAP.md`](ROADMAP.md) 为准。核查 2026-10-26（v2.60.1）。
>
> **本文件中的方向均未批准开发**，不构成 Sprint 计划。正式执行仍用项目现有的 Sprint 编号、
> 工作项编号（R-nn / U-nn）与版本规范。

## 1. 产品定义

Character Studio 是面向 OC / 原创角色创作者的**本地优先、以角色为中心的关联式创作资料工作台**。
它服务角色设计、世界观创作、剧情规划、关系整理、企划管理与长期设定积累。

产品核心不是功能数量，而是让创作者能够：

- 可靠保存角色与世界观设定；
- 高效创建、编辑、查找、管理内容；
- 在角色、事件、地点、组织之间建立**明确关联**；
- 从不同角度探索同一个原创世界；
- 用时间线理解故事发展；
- 用可视化关系画布表达复杂的人物与世界关系；
- 自由扩展角色属性与创作资料；
- 掌握本地数据、备份与恢复的控制权。

## 2. 三层产品理念

**先让资料互相关联，再让资料结构更自由，最后扩展实际创作能力。**

| 层 | 内容 | 判断标准 |
| --- | --- | --- |
| 第一层：可靠的资料管理 | 角色、事件、世界观、关系、素材能稳定保存、读取、搜索、编辑、恢复 | 任何时候关掉浏览器再打开，资料都在；备份能验、能恢复 |
| 第二层：可探索的关联网络 | 内容有稳定身份，可引用、可双向追踪、可跨模块跳转 | 改名不丢引用；从角色能走到它参与的事件，再走回来 |
| 第三层：面向创作的表达能力 | 自定义字段、多图资料、事件时期、动态关系、更好的内容编辑 | 新能力长在既有工作流上，而不是另起一套 |

三层有依赖但不要求一次大重构完成；允许在第二层尚未完全铺开时先做第三层里独立的部分
（如自定义字段、多图），前提是不破坏第一层。

## 3. 差异化重点

优先深化：高质量角色档案管理、自由可定制的关系画布、角色与世界观的双向关联、
清晰可读的事件时间线、本地数据完整性与恢复能力、灵活而不过度复杂的创作工作流。

**不以功能覆盖数量作为目标。** 判断一个方向值不值得做，先看它是否让上面五项更强。

| 能力 | 现状 | 证据 |

## 5. 方向 A：统一实体与跨模块关联（长期最重要的技术方向）

### 5.1 要解决的问题

资料变多后，同一角色/地点/组织会在多个模块被反复描述。若只存名称文本，会出现：改名后别处
仍是旧称、事件改期后关联资料不更新、删除条目后留下失效引用、同一设定被复制成多份并逐渐
不一致、无法查询「这个地点被哪些事件用到」。

### 5.2 目标能力

- 实体身份可解析：ID + 类型 + 目标解析；
- 正向关联与**反向引用查询**；
- 重命名兼容；
- 删除与失效引用的明确处理；
- 跨模块导航并能返回来源。

不同实体保留各自结构，不要求塞进一张通用表。

### 5.3 一致性原则

- 同一属性只有一个权威来源，其他位置通过引用读取，而不是复制后再各自维护。
- 区分**业务数据关系**与**界面呈现状态**：画布上移动节点只改布局，不改关系；
  改视觉分组不等于改阵营；换连线样式不等于换关系类型。

### 5.4 实施顺序（渐进，不整体替换存储）

1. 核实已有 ID 与关联读取点；
2. 找出真正缺稳定 ID 的关联场景；
3. 设计可复用的引用解析接口；
4. 选一个真实场景做最小纵向切片；
5. 验证改名、删除、导入、恢复；
6. 再扩展到其他实体类型。

**验收目标**：改名不丢引用、跳转正确、删除影响范围明确、备份恢复后关联一致。

## 6. 方向 B：文本引用与全局检索

### 6.1 文本内引用

目标：在角色背景、事件描述、世界观正文里提到已有设定时，能插入**稳定引用**而不是打一遍名字。

候选：`@` 触发候选、按名称检索实体、显示类型与辨识信息、保存实体引用、点击跳转、返回原位置、
目标改名后仍有效、目标删除后显示失效。

边界：第一版不做完整富文本编辑器；先评估现有文本字段能否承载轻量引用；若需新存储格式，
必须同时设计版本兼容、旧文本保留与导入恢复规则。**不得用全局名称替换冒充稳定引用。**

### 6.2 全局搜索

目标：不必先知道内容属于哪个模块才能找到它。

候选：跨实体名称搜索、按类型分组、显示必要上下文（类别/所属世界/上级条目）、直接定位、
键盘快速打开；**保留**现有模块内搜索与筛选。

策略：可独立于完整引用体系先做，但必须复用现有导航逻辑与稳定 ID；不新增与现有搜索竞争的
第二套入口。现状：Dashboard 已有 `Cmd/Ctrl+K`，先核实现有快捷入口能否扩展。

**验收目标**：用户能快速找到并引用已有内容，不必手工重复输入与维护名称。

## 7. 方向 C：角色自定义字段与模板

不同题材（现代、奇幻、科幻、兽人/Furry 等）需要的属性不同；继续加固定字段会让编辑器越来越长。

- **系统字段**：ID、名称、必要关联等维持系统运行的信息，不可由用户删除。
- **扩展字段**：用户自建、命名、排序、分组；初期支持文本、多行文本、数字、日期、是/否、单选。
- **模板**：可复用的字段组合作为起点，但不限制用户继续编辑。

约束：旧角色升级后仍可编辑；扩展字段必须进入完整备份与恢复；字段名冲突不得覆盖数据；
删除字段要提示影响；类型变更需定义转换或阻止不安全操作；**不做**公式字段、脚本字段、任意嵌套。

**验收目标**：不同类型角色能自定义属性，且旧角色与备份正常兼容。

## 8. 方向 D：多图与素材管理

头像是单图，承载不了完整视觉设定（立绘、服装、表情、草稿、色板、参考、委托）。

分三步，不直接建大相册：

1. **单角色多图**：多张图、基本分类/说明、查看详情、来源或作者、归属明确；
2. 世界观条目与事件可关联图片；建立素材索引；从素材跳回相关角色；
3. 再研究集中相册、跨实体共享与重复资源管理。

技术边界：优先复用现有 IndexedDB 与头像素材逻辑；关注大图容量、重复上传、导出体积、
导入合并与 ID 冲突、删除对象后的图片保留策略、本地恢复、配额不足时的行为。
**不得因为加图片而削弱完整备份的可靠性。**

历史编号 U-84（时间线/世界观配图）与本方向合并核对，不重复立项。

**验收目标**：多张设定图能可靠保存、组织、查看，并完整进入备份。

## 9. 方向 E：时间模型与动态世界

### 9.1 从时间点到时间段

现状：事件是单一日期（+ 可选地点、类型、关联角色）。候选：开始时间、可选结束时间、
持续事件的时间轴展示、纪元/时期显示、未结束事件的明确状态。

需兼容既有日期与纪年规则；**不把单日期事件强制改成必填起止**。

### 9.2 角色人生轨迹（R-18）

在角色资料内按阶段展示关联的关键事件。核心原则：**引用现有事件，不另建一套事件数据**；
改原事件后轨迹读到最新信息。

### 9.3 动态关系（R-19）

关系可带生效/失效时间或阶段，图谱可切换「当前 / 某一时期」。它需要明确的时间模型与冲突
处理规则，**不与时间段事件同时大规模开发**。

**验收目标**：持续事件与动态关系无需复制资料，跨页面修改保持一致。

## 10. 关系画布的长期演进

现有自由画布（拖拽布局、视觉分组、自动整理、外观预设、样式定制、导出）是长期优势，
**应尽可能保留而不是重写**。可研究：扩展到多种实体类型（角色↔地点、角色↔组织、组织↔组织）、
从图谱查看关联实体、受控的业务关系编辑、不同时期的关系展示、高密度世界观图谱可读性。

红线：图谱布局数据 ≠ 实体真实关系；移动节点 ≠ 改关系；改分组 ≠ 改阵营；换线样式 ≠ 换关系类型。
混合实体图谱属中长期，不得影响当前角色关系图的稳定使用。

## 11. 内容编辑能力

适度增强长文本体验：标题与段落层级、更好的长文本阅读布局、轻量排版、实体引用、必要的图片
嵌入、内容导航与快速定位。不要求立即引入复杂富文本编辑器。

远期研究（**未立项**）：完整小说创作系统、章节管理、字数目标、多格式输出、地形生成与地图编辑、
原生客户端。启动与否取决于真实需求、维护成本与工作台的关联程度。

## 12. 本地优先与数据安全

继续本地优先，**不主动规划**账号体系、强制云同步或必须依赖在线服务的功能。

必须准确表述边界：本地保存不等于永久保存；浏览器数据仍可能被清理、受配额限制或随设备损坏；
用户需定期导出完整备份；备份必须能验证与恢复；关联、自定义字段、图片都必须纳入备份范围。
**不得宣称绝对隐私安全、绝对不会丢数据、不存在任何泄露可能。**

新增数据类型时必须验证：旧数据兼容、导入与恢复、ID 重映射、引用完整性、写入失败、删除与撤销、
备份格式变化时的迁移。只在确有需要时改存储格式。

## 13. 阶段与依赖（A–E 是方向，不是 Sprint）

| 方向 | 前提 | 验收目标 |
| --- | --- | --- |
| A 关联基础 | 核实现有 ID / 关联读取 / 导航 / 反向查询 | 改名不丢引用、跳转正确、删除处理明确、恢复后一致 |
| B 引用交互与全局检索 | A 的稳定引用 | 能快速找到并引用已有内容 |
| C 角色字段自由度 | 无强依赖，可独立排期 | 可自定义属性且旧数据兼容 |
| D 多图与素材 | 无强依赖，可独立排期 | 多图可靠保存、组织、查看、备份 |
| E 故事时间与动态世界 | A + B（要引用与跳转） | 持续事件与动态关系不复制资料 |

优先关系：**现有数据核实 → 稳定引用 → 引用交互与双向跳转 → 更复杂的跨实体能力。**
C 与 D 可按用户价值插队，但每轮只做**一个完整场景**。

## 14. 优先级（不代表已批准）

| 级别 | 方向 | 现有编号 |
| --- | --- | --- |
| 高 | 跨模块引用与反向关联、全局搜索与快速跳转、角色自定义字段 | R-20（世界观与故事联动）覆盖其中一部分 |

优先级不等于批准；不得因为某项看起来丰富就牺牲稳定性、易用性与维护成本。

## 15. 开发与验收规范（交给 Codex）

1. 核实当前代码与版本；2. 对照本文件确认需求**是否已实现**（先看 §4）；
3. 写清一个具体用户操作流程；4. 定最小可交付范围；5. 完成数据/界面/交互；
6. 跑受影响单测、`typecheck`、构建；7. 按风险做定向浏览器验证；
8. 数据变更加完整备份往返测试；9. 更新 Sprint / CHANGELOG / 状态文档；10. 按发布规范交付。

避免：重复审查整个项目、每次改动都跑全部浏览器测试、提前造没人用的通用接口、
未验证兼容就改存储结构、借文档整理夹带新功能、把长期规划写成已完成。
