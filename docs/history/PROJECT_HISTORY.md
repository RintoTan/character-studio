## 1. 编号规范（自 2026-10-26 起统一）

| 名词 | 含义 | 例子 | 权威来源 |
| --- | --- | --- | --- |
| **Version** | 应用正式版本，`MAJOR.MINOR.PATCH` | v2.60.1 | `package.json` + `src/config/version.ts`，`pnpm verify:version` 校验 |
| **Sprint** | 开发迭代编号，跨版本连续 | Sprint 50、Sprint 53.2 | 仓库既有编号，不回退、不重编 |
| **Phase** | Sprint **内部**阶段（如「阶段 A：数据可靠性」），不是长期编号 | Sprint 38.2 / 阶段 B | `docs/DEVELOPMENT_LOG.md` |
| **KI-nn** | 已知问题编号 | KI-15 | `docs/KNOWN_ISSUES.md` |
| **U-nn / R-nn** | 需求/研究候选编号 | U-84、R-18 | `docs/ROADMAP.md` |

记录格式：`Sprint / 工作项 / 版本 / 提交 SHA / 日期 / 状态`。Sprint 与版本**不强制一一对应**
（历史上存在一个 Sprint 连发多个 patch，也存在一个版本跨两个 Sprint）。

早期的「第一阶段…第二阶段」不是独立编号体系：它们对应 Sprint 内部的阶段划分，本文 §2
按阶段归档，并保留原阶段名，不做重新编号。

   没有一份完整对照表。本表只按时间区间聚合，未编造逐 Sprint 对应。

4. **早期「阶段 1–5」的内部阶段名**保留在 `DEVELOPMENT_LOG.md`，未强行映射到 Sprint 编号。
