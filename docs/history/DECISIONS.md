# 技术决策记录（ADR 索引）

> [`../DATA_FORMATS.md`](../DATA_FORMATS.md)。核查：2026-10-26 / v2.60.1。

格式：`编号 · 决策 · 时间 · 状态（生效 / 已作废）`。

## D-01 本地优先，不做后端与云同步
**生效**（2026-06 起）。

理由：单人创作工具，数据敏感且量小；localStorage + IndexedDB 足以支撑，省掉账号、同步冲突、
服务端运维。代价：换设备只能靠导出/导入；浏览器清数据即丢失，所以必须有备份与恢复点。
后果：`docs/ROADMAP.md` 里**不再把云同步列为未来项**（2026-10-25 文档终检把「将来会做」
改成已作废）。任何「顺手加个同步」的改动都要先推翻这条。

## D-02 备份是四域快照 + 恢复点，而不是导出单表
**生效**（2.12.0 起，2.59.7 明确措辞）。

理由：四个域互相引用，单表导出会产生悬空引用。快照在**覆盖之前**写入，回滚读同一份快照。
代价：备份体积大。后果：`character-studio.backup` 与 `workspaceBackup.ts` 分离；导入必须做
ID 映射。

## D-03 删除可恢复
**生效**（Sprint 38.2 / 2026-10-16）。

理由：删除是全应用唯一不可逆操作；一处误删会连带清掉关系与事件引用。做法：删除前写
`character-studio.delete-recovery` 快照，恢复时按 ID 合并，重复撤销幂等。后果：三个入口
（主页单删、批删、编辑器删除）都必须走同一条路径，`test/deleteEntryPoints.test.ts` 渲染真实
`App` 来守卫「接线点」而不是算法。

## D-04 跨实体只存 ID，不存副本
**生效**（全程）。

理由：角色改名不应造成历史记录里出现旧名字。代价：显示时要 join，删除时要级联清理。
后果：`referenceIntegrity.ts` 负责清理，导入导出必须建立旧→新 ID 映射。

## D-05 关系网从「关系管理」走向自由画布
**生效**（2.37 起，Sprint 49/50 成型）。

理由：用户需要的是「看见结构并自己排布」，不是表格。做法：SVG 画布 + 坐标持久化
（`relationship-layout`）+ 命名布局快照 + 外观预设（`CanvasStyle`）。代价：渲染与手势复杂度
上升，密集节点需要降级渲染。后果：拖动/缩放手势算法**不再随意改写**（改一次要重跑一族检查）。

## D-06 外观预设与用户覆盖分离
**生效**（Sprint 50）。

理由：预设是**一组初始值**，不是锁定样式；用户微调后不应被预设「拉回去」。
做法：`style.preset` 记录来源，用户改动即变 `custom`；`normalizeCanvasStyle` 返回深拷贝，
避免共享默认对象被就地改写（曾经因为按引用返回导致默认值被污染）。后果：预设数量与语义
受保护，新增字段不能破坏 `custom` 状态。

## D-07 Mantine 作为 UI 基础层
**生效**（2.60.0）。

理由：编辑器控件（单行/多行/选择）自研成本高、无障碍细节容易漏。做法：只迁移**输入控件**，
页面骨架、画布、工具栏保持自有样式与 class 名。代价：库的内部 class（`mantine-*`）与
combobox 语义要自己补（`aria-expanded`）；自动化测试不能直接 `click()` 打开 Select，要发
`ArrowDown`。后果：定位器审计把 `mantine-` 前缀列为「库发出的类名」豁免，产品类名仍须实判。

## D-08 中文正文用 `em` 而不是 `ch`
**生效**（Sprint 42–43）。

理由：`ch` 基于「0」的宽度，中文字体下与汉字宽度不成比例，68ch 实测约 47 个汉字。
做法：正文量宽统一 `40em`（约 40 汉字/行）。后果：时间线与世界观阅读列都以此为准，
不要混用两种单位。

## D-09 移动端是独立布局，不是缩放
**生效**（2.37 起）。

理由：375px 下工具栏放不下四个控件 + 文字按钮。做法：≤720px 折叠为图标 + 抽屉，
底部固定操作坞，工具栏用栅格。后果：任何桌面布局改动都要回头确认 320/375/390/430 不溢出；
「一行化」是通过减少可见标签实现的，不是缩小控件。

## D-10 检查失败先判性质：产品 / 探针 / 环境
**生效**（贯穿 2.40+）。

理由：多次把探针缺陷误判成产品缺陷（读到旧 DOM、观测点没有区分度、`setPointerCapture` 吞
click、长会话 CDP 积压）。做法：README/AGENTS 里固定三步——复现、换观测点验证、短会话隔离
重跑。后果：报告必须区分「产品缺陷」「测试环境问题」「未验证」，SKIP/TIMEOUT 不算通过。

## D-11 Sprint 与版本不一一对应
**生效**（2026-10-26 规范化）。

理由：一个 Sprint 可能连发多个 patch，一个版本也可能横跨两个 Sprint。做法：见
[`PROJECT_HISTORY.md`](PROJECT_HISTORY.md) §1 的编号规范；`Phase` 只作 Sprint 内部阶段，
不再作为独立长期编号。

## D-12 Developer Center 只做诊断，不做功能入口
**生效**（2.59.7 – 2.59.8）。

理由：曾经出现「开关已接线但无消费者」的假配置。做法：四个不可达分区下线；每个开关必须有
真实读取点，并有反向突变测试守卫。后果：新增开关必须同时给出消费者与测试。
