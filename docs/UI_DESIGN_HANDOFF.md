## 1. 项目定位与用户类型

**Character Studio** 是一个**本地优先**的 OC（原创角色）创作工作台。纯前端，无账号、无服务器、不上传数据；文字进浏览器 `localStorage`，头像二进制进 `IndexedDB`。

**它像什么**：Apple 的克制、Linear 的清晰层级、Notion 的信息组织。**它不像什么**：营销落地页、炫技 Demo、数据密集的后台管理系统。

| 用户类型 | 他们来时想做什么 | 对 UI 的真实要求 |
| --- | --- | --- |
| OC 创作者（核心） | 把脑子里的角色写下来、反复改、看一眼整体 | 长表单不能压迫；写的时候少干扰；预览要「像一张设定稿」 |
| 小说 / 跑团 / 乙游 / 企划作者 | 管理几十上百个角色，按世界观分组找 | 列表要能扫；搜索要快；状态（草稿 / 收藏 / 置顶）一眼可辨 |
| AI 绘图 Prompt 整理者 | 生成并复制中英 Prompt | Prompt 区块要清晰、可复制、可编辑 |
| 关系 / 世界观创作者 | 把角色放进世界（关系网、时间线、条目层级） | 图要能读、表要能查；两者数据一致 |

**使用场景的关键事实**：这是一个**长时间停留**的工具（写设定），也是一个**间断回来**的工具（改一个字段）。两种模式对首屏信息量、吸顶行为、暗色可用性的要求不同。

## 3. 各页面的结构与用户流程

### 3.1 主页

```text
[ 顶栏：Logo ｜ 工作区切换 ｜ 主题 ]
┌ Hero ──────────────────────────────────────────┐
│ OC WORKSPACE                                   │
│ 角色列表 / 搜索·筛选结果 / 收藏角色 / 草稿角色   │
│ 全部 N ｜ 收藏 N ｜ 草稿 N      ← 三个统计入口   │
└────────────────────────────────────────────────┘
┌ 角色列表 ─────────────────────────┬──────────────┐
│ 角色列表 N                         │ 搜索 筛选 视图 新建 更多 │
└────────────────────────────────────┴──────────────┘
   卡片视图（>30 角色时按世界观分组，组头吸顶可折叠）
   或 表格视图（逐行选择）
[ 浮动栏 ]                                   [ 页脚 ]
```

**关键流程**：进入 → 扫列表 → 搜索/筛选定位 → 打开（编辑或预览）→ 或批量处理（选择 → 批量编辑/收藏/复制/导出/删除）。

**界面上最容易出问题的地方**：工具栏五个控件必须与列表标题同行且贴右缘；筛选是**浮层**（不推列表）；删除后有撤销 Toast。

### 3.2 角色编辑工作台

```text
[ 顶栏 ]
┌ 操作栏（吸顶）──────────────────────────────────────┐
│ ● 已保存   [随机生成角色]        [返回][预览][更多][保存角色] │
└─────────────────────────────────────────────────────┘
┌ 左：模块导航 ─┬ 右：表单 ───────────────────────────┐
│ 已完成 3/6     │ 基础信息   （字段网格）              │
│ ├ 基础信息     │ 外貌设定   （字段网格 + 随机灵感 清空）│
│ ├ 外貌设定     │ 性格设定                            │
│ ├ 性格设定     │ 个人偏好                            │
│ ├ 个人偏好     │ 能力设定                            │
│ ├ 能力设定     │ 背景故事                            │
│ ├ 背景故事     │ AI Prompt（中文关键词 / 英文 Prompt）  │
│ ├ AI Prompt    │                                     │
│ 跳到下一个未完成 │                                     │
└───────────────┴─────────────────────────────────────┘
[ 页脚：清空 · 删除 ｜ 取消 · 临时保存 · 保存角色 ]
```

**关键流程**：写 → autosave / 手动保存 → 预览 → 返回继续改 → 保存（落到该角色的预览页）。

**这是全站最需要设计关注的一页**：它最长、停留最久、承载最多的辅助动作（随机生成、随机灵感、清空、复制、重新生成、头像选择/裁剪）。

### 3.3 角色预览页

```text
[ 顶栏 ]
┌ Hero：头像 ｜ Character Preview ｜ 角色名 ｜ 职业 / 世界观 ┐
│            [ 编辑 ][ 收藏 ][ 导出 ][ 返回 ]  ← browse 模式  │
│            [返回编辑][保存草稿][删除角色][保存角色] ← editing │
└──────────────────────────────────────────────────────┘
┌ 基础资料卡 ────────────────────────────────────────────┐
┌ 性格标签 ┐┌ 视觉风格 ┐
┌ 外貌 ──────────────┐┌ 能力 ──────────────┐
┌ 背景故事 ──────────┐┌ 个人偏好 ──────────┐
┌ 中文关键词 ────────┐┌ 英文 Prompt ───────┐
┌ 时间信息 ┐
[ 浮动栏 ]
```

**已知的设计抱怨**：用户反馈「界面平淡、信息分散、无层次」（属设计评估，不是缺陷）。这一页是本次交接的**首要改版对象**。

### 3.4 角色关系网

```text
┌ 角色关系网 ────────────────────────────────────────────┐
│ RELATIONSHIPS                                          │
│ 角色关系网                    [−][100%][+] [只显示有关联的 8] [新建关系] │
│ N 个角色 · M 条关系                                      │
├────────────────────────────────────────────────────────┤
│                    〔径向图〕                            │
├────────────────────────────────────────────────────────┤
│ 头像 小 中 大 ｜ 名称 小 中 大 ｜ 分辨率 1x 2x 3x  ｜ JPG PNG PDF │
├────────────────────────────────────────────────────────┤
│ 关系列表  M 条 · 互为关系不分方向，师承指向学习的一方        │
│ 关系 ｜ 角色 ｜ 另一方 ｜ 备注 ｜ 操作                     │
└────────────────────────────────────────────────────────┘
```

**关键事实**：图与表是**同一份数据**的两种读法（数据不被锁在图形里）；图上方有三个控件、下方有一整条画布栏，凡是新控件都要先问「它属于图还是属于表」。

### 3.5 世界观时间线 / 世界观管理

```text
┌ 世界观时间线 ────────────────────────┐   ┌ 世界观管理 ──────────────────┐
│ TIMELINE          [返回][新建事件]    │   │ WORLD        [返回][新建条目] │
│ N 个事件 · M 个年份                   │   │ N 个条目 · M 个分类           │
├──────────────────────────────────────┤   ├──────────────────────────────┤
│ 2024                                 │   │ 地点 · 3                      │
│  └ [起源] 2024-05-01  [编辑][删除]    │   │  └ 北境        [展开][编辑][删除]│
│    初次相遇                           │   │    └ 霜堡                      │
│    地点：…  描述…  [角色 chip]        │   │ 势力 · 2                      │
│ 2026                                 │   │  └ …                          │
└──────────────────────────────────────┘   └──────────────────────────────┘
```

两页结构一致：**标题 + 副行 + 两个工具栏按钮 + 分组列表**。设计上应与主页的列表语言同族。

### 3.6 开发者中心

左侧锚点导航 + 右侧 9 张设置卡片（Project / 品牌资源 / 设计系统 / 内容中心 / Prompt 中心 / 应用配置 / Export / Developer Tools / Experimental）。**注意**：这不是面向普通作者的功能，但它的「设计系统」卡片是**运行时主题的实际控制台**（强调色、圆角、阴影强度、动效、字体缩放、紧凑模式）。

## 4. 现有设计系统与组件规范

完整令牌表见 `docs/UI_AUDIT.md` 第 2 节。以下是设计智能体**必须沿用或明确偏离**的规范：

### 4.1 令牌（现状）

| 类别 | 令牌与值 |
| --- | --- |
| 语义色 | `--bg` `--surface` `--surface-subtle` `--text` `--text-soft` `--muted` `--border` `--border-strong` `--primary` `--primary-hover` `--on-primary` `--danger` `--danger-bg` `--danger-border` |
| 中性填充 | `--control-fill`（text 7% 混 surface）、`-hover`（12%）、`-active`（17%） |
| 圆角 | 输入 `--control-radius: 8px`；卡片 / 面板 / 弹窗 `--developer-card-radius: 8px`；按钮 `--developer-button-radius: 10px`；浮动按钮 999px |
| 高度 | 带文字控件 `--control-height: 42px`；图标控件 `--control-height-icon: 36px`；紧凑档 `--control-height-compact: 34px` |
| 内边距 | 面板 24 / 卡片 16 / 侧栏 12 |
| 阴影 | 两档：`--shadow`、`--shadow-strong`（强度可配置：none / soft / medium / strong） |
| 动效 | `--duration-fast: 150ms`、`--duration-medium: 190ms`、`--ease-standard: cubic-bezier(.2,0,0,1)`；`prefers-reduced-motion` 有 3 条规则 |
| 层序 | 内联 5–40 ／ 浮层 120–160 ／ 弹窗 900·910 ／ Toast 1000 |
| 字体 | `Inter` 为首选（**注意：`DESIGN` 原则要求避免默认栈，但这是既有项目的既定选择，改动属于品牌决策，需用户同意**）；Emoji 栈挂在根字体末尾 |
| 标签色 | `.tag-tone-0…17`，18 组深浅各一套，按文字 Hash 稳定取色 |

### 4.2 组件规范（现状）

| 组件 | 规范 |
| --- | --- |
| 主按钮 | 实心强调色 + 自动对比色文字；hover 用推导出的 `--primary-hover` |
| 次要 / 描边（ghost） | 中性填充、无描边；hover 加深 |
| 危险按钮 | **中性填充 + 危险色文字**（不用大红块）；hover 才泛红底 |
| 图标按钮 | 36×36 正方形；`2px` 透明边框保持尺寸稳定 |
| 浮动按钮 | 44×44（触控下限），胶囊容器一层阴影 |
| 输入 / 下拉 | 圆角 8px；焦点用 `--focus-ring` |
| 卡片 | 1px `--border` + 圆角 8px + `--shadow`；**不卡片套卡片** |
| 弹窗 | Header（eyebrow + 标题 + 关闭）+ 内容 + Footer（取消为次要、确认为主） |
| 菜单 | 圆角、阴影、hover 清晰、不被父容器裁切、点击外部与 Escape 关闭、同时只开一个 |
| Toast | 四语义类（success / warning / error / loading），单计时器 1.8s |

### 4.3 响应式断点（现状）

`1024px` · `860px` · `720px`（主力断点，约 160 条规则） · `430px`；触控设备有 `overscroll-behavior` 与 `(hover:none)` 规则。

**硬性技术约束（不是设计偏好）**：`body` 必须是 `overflow-x: clip` + `overflow-y: visible`。若改成 `overflow-y: auto`，**全站 `position: sticky` 会静默失效**（编辑页侧栏与操作栏都会不动）。

## 5. 必须保留的功能和交互

设计改版**不得**移除或改变下列行为。每一条都有数据或测试依据。

### 5.1 数据与流程

1. **六节模块结构**：基础信息 / 外貌设定 / 性格设定 / 个人偏好 / 能力设定 / 背景故事 / AI Prompt（后两者中的「个人偏好」与「AI Prompt」可被 feature flag 隐藏，隐藏时导航与完成度计数必须同步）。
2. **保存语义**：四条写角色路径（保存角色 / 另存草稿 / autosave / 离开提示）共用同一套「什么算已保存」规则。「已保存 / 未保存 / 正在保存 / 保存失败」必须仍可读。
3. **保存已有角色落到该角色的预览页**（不是主页）。
4. **草稿与正式角色分离**：`isDraft` + `draftOfId`；同一个来源角色只保留一份草稿。
5. **删除语义是「断开」不是「连带删除」**：删角色会从时间线与世界观条目里移除该角色的关联，**但事件与条目保留**；删世界观父级时子级脱离为顶层。
6. **收藏是 quick access**：不更新 `updatedAt`，不参与排序因子（否则卡片会跳位）。
7. **导入必须「解析 → 预览 → 确认 → 写入」**，取消不写任何数据；覆盖前写自动快照。
8. **导入按 id 合并，不覆盖**（备份是「当时有什么」，恢复它不该删掉备份之后新建的东西）。

### 5.2 入口与状态

9. **搜索面板进入页面恒为关闭**（不变量）。`/` 与跨页搜索信号打开的是**搜索框**，不是筛选面板。
10. **搜索关键词在收起后保留**，图标以 active 标记「列表正在被过滤」。
11. **筛选面板的字段与状态**（范围 / 排序 / 世界观 / 性别 / 视觉风格 + 清空）不得改变含义。
12. **「清空筛选」重置排序，「编辑器删除后重置」不重置排序** —— 这个差异是刻意的。
13. **卡片视图 >30 角色时按世界观分组**，组头吸顶、可折叠、按组大小排序（分组与折叠是会话级状态）。
14. **表格视图逐行选择**与卡片视图的选择是同一套 `selectedIds`；表格的状态列必须与卡片视图读同一组徽章（正式/草稿 + 置顶 + 收藏）。
15. **顶栏工作区菜单的 4 个入口按 feature flag 门控**（没发布的模块不得出现死入口）。

### 5.3 交互

16. **Escape 关闭所有已声明的层**，包括破坏性确认框（在那里 Escape 等于取消）。
17. **点击外部关闭**下拉 / 卡片菜单 / 命令面板 / 弹窗（点背景）；菜单与弹窗互斥。
18. **同时只打开一个菜单**；一个弹窗换成另一个弹窗时必须重新计算（不是「有弹窗」这个布尔量）。
19. **快捷键**：`N` 新建、`/` 搜索、`Esc` 关闭、`Enter` 打开首个搜索结果、`Cmd/Ctrl+K` 命令面板、`Cmd/Ctrl+S` 保存。输入控件聚焦时不得干扰输入。
20. **析构性操作必须二次确认**，且确认文案要与实际影响一致（例如「将删掉这些角色」而不是泛泛的「确定吗」）。
21. **列表吸顶头必须不透明**（半透明会让滚过的行透出来，被误读成错位）。
22. **关系网：滚轮只缩放、不带走页面**；单指平移、双指缩放；点击节点进入角色（拖动过则不触发）。
23. **关系网的方向语义**：互为类（亲属/友人/对手/敌对/同僚/情感/其他）不画箭头、读作 `↔`；师承画箭头、读作 `→` 且字段名变为「师承方 / 学习方」。
24. **重复关系必须被拒绝并说明原因**（不能静默无反应）。

### 5.4 可访问性（已在渲染层核验过，不得回退）

25. 正文与辅助文字对比度达 WCAG AA；主按钮文字颜色按强调色亮度自动取值（强调色可由用户改）。
26. 允许双指放大（不得声明 `user-scalable=no` / `maximum-scale=1`）。
27. 开关控件带 `role="switch"` 与 `aria-checked`。
28. 无无名可聚焦控件、无缺 `alt` 图片、375px 无横向滚动。
29. 焦点可见（`--focus-ring`）。

### 待验证的设计假设（不得当作缺陷）

- 「预览页界面平淡、信息分散、无层次」—— 这是设计评估，也是本次交接**最有价值的输入**。
- 「首次 About 排版需要精简」、「预设下拉与输入框同文案重复展示」、「375px 列表标题被截断 2px」、「裁剪弹窗残留 `position: sticky`」—— 均需用户确认是否要做。

---

## 7. 设计目标与不可突破的限制

### 7.1 设计目标

1. **预览页要有「一张设定稿」的说服力**：清晰的层级、明确的阅读顺序、能直接交给别人看。
2. **编辑页长表单要「不累」**：节与节之间节奏一致、辅助动作可预期、吸顶与状态反馈稳定。
3. **主页要能「扫」**：40–120 个角色时，一眼看出状态与分组，两秒内定位到一个角色。
4. **弹窗与文字语言要统一**：中文化、宽度成阶梯、未发布功能不冒充已发布。
5. **深色与浅色是同一套设计**：不是浅色加反色，两套都要能在渲染层核验通过。

### 7.2 不可突破的限制

| # | 限制 | 原因 |
| --- | --- | --- |
| 1 | **不得修改应用源码、数据逻辑、存储键或配置**（除非用户单独授权，并另行评审） | 本次是设计交接，不是开发任务 |
| 2 | 不得改变任何**数据格式**：`localStorage` 键名、IndexedDB 库名与结构、JSON / ZIP / CSV 的字段 | 会破坏旧备份与已有用户数据 |
| 3 | 不得移除或改变第 5 节列出的功能与交互 | 其中多数有单测或实测证据保护 |
| 4 | 导出区域的样式**不能使用** `oklch()` / `color()` / `lab()` | html2canvas 的颜色解析器只认 rgb / rgba / hsl / hex（现有代码用克隆期降级兜底，但新增现代颜色函数仍需复核） |
| 5 | 不得让 `body` 变成滚动容器 | 全站 `position: sticky` 会静默失效 |
| 6 | 本地优先、无服务器 | 产品定位 |
| 7 | 不得声明禁止缩放 | 可访问性 |
| 8 | 不改动 `Character` 类型、`characterStorage.ts`、`avatarAssets.ts`、`importExport.ts` 的备份结构、`AvatarDisplay`、`localStorage` 键、IndexedDB store 名 | 项目手册明确列为「核心稳定层」 |

### 7.3 必须交付的两种状态

任何页面方案都必须给出**浅色与深色**两套，并且**桌面（1440）与移动（375）**各自的布局与信息取舍。

## 8. 页面改版优先级

| 顺序 | 页面 / 区域 | 理由 | 依赖 |
| --- | --- | --- | --- |
| 1 | **角色预览页** | 用户明确反馈「平淡、分散、无层次」；它也是导出与分享的门面 | 无 |
| 2 | **设置弹窗** | 有明确的具体问题（宽度 / 语言 / 分组），改动面小、收益直观 | 需用户确认「未发布功能」的分组方式 |
| 3 | **角色编辑工作台（六节统一）** | 最长、停留最久的一页；当前节与节之间不一致 | 需先有一次几何基线，否则无法证明「只统一了外观」 |
| 4 | **主页** | 结构已在 2.26.0 收敛为四层，主要问题是卡片与表格的信息密度与视觉节奏 | 无 |
| 5 | **关系网** | 2.27.0 刚返工过控件与对齐；下一批应先补三档视口基线再动 | 需先补 1440/900/375 实测 |
| 6 | **时间线 / 世界观管理** | 结构与主页列表同族，可在主页语言定稿后一起统一 | 依赖第 4 项 |
| 7 | **开发者中心** | 面向协作者而非普通用户，优先级最低 | 无 |
| 8 | **浮动栏「贴近主栏」** | **被阻塞**，需用户先说明「主栏」指什么 | 用户输入 |

## 9. 需要设计智能体交付的成果

对每个被选中的页面 / 区域，交付以下内容（**不要求写代码**，但如果给代码片段，必须是可直接套用的 CSS/JSX 建议并说明影响面）：

1. **目标陈述**：这一页要解决什么用户问题，成功是什么样。
2. **信息架构**：区块的层级与顺序，以及**为什么是这个顺序**（阅读动线）。
3. **布局方案**：桌面（1440）与移动（375）两版；关键尺寸、间距节奏、区块宽度与对齐基线。
4. **组件规格增量**：沿用哪些现有令牌与组件；需要新增 / 修改哪些，并给出与现有规范的差异说明。**不得凭空发明与现有令牌冲突的颜色或圆角。**
5. **状态覆盖**：空状态、加载中、无结果、错误、成功反馈、禁用态。
6. **主题覆盖**：浅色与深色两套；标注哪些值必须来自令牌、哪些需要新的令牌。
7. **响应式与可访问性**：断点行为、键盘可达性、焦点顺序、对比度与触控目标尺寸。
8. **交互说明**：新的或改动的交互，以及**与第 5 节「必须保留」清单的一致性论证**。
9. **改动范围与风险**：涉及哪些文件 / 样式区块；哪些属于纯呈现层（可安全改），哪些会牵动数据或逻辑（必须另立任务）。
10. **验收标准**：可被第三方逐条核对的清单（几何数值、对比度、无横向溢出等）。

## 10. 明确禁止事项（给设计智能体）

1. **不得未经授权修改代码、样式文件或数据逻辑。** 交付物是方案文档（Markdown / 设计说明），不是直接落地的补丁。
2. **不得改变任何存储键、数据格式或导入导出结构。**
3. **不得移除第 5 节列出的功能、入口或交互。**
4. **不得把未验证的观感当成缺陷去「修复」。** 若你认为某处是问题，请标注「假设 + 需要的证据」。
5. **不得引入与现有设计语言冲突的新颜色 / 新圆角 / 新字号阶梯而不说明理由。**
6. **不得声称已完成渲染层验证。** 任何「看起来没问题」都必须标注为未验证；需要实测的部分请显式列出验证方法。
7. **不得改动下列「核心稳定层」**：`Character` 类型、`characterStorage.ts`、`avatarAssets.ts`、`importExport.ts` 的备份结构、`pdf-safe` 样式、`AvatarDisplay`、`localStorage` 键名、IndexedDB store 名。
8. **不得把本交接包中的「设计目标」当成已批准的需求** —— 它是候选方向，需用户确认。

## 11. 建议的第一步

1. 读 `docs/UI_AUDIT.md` 第 1 节（页面与布局清单）与第 2 节（设计系统盘点），建立现状事实。
