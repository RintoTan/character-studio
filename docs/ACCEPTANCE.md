# Character Studio —— 验收与证据索引

> 本文件是**验收材料的地图**，不是验收报告。每轮的结论写在 `CHANGELOG.md`，当前状态写在
> `PROJECT_STATUS.md`；这里只回答「哪一轮的证据在哪、它能证明什么、现在还算不算数」。
> 最近整理：2026-10-22（2.53.0）。

---

## 1. 验收分三层，先看层再看图

| 层 | 入口 | 能证明 | 不能证明 |
| --- | --- | --- | --- |
| 单元测试 | `npm test` | 纯函数、事务、存储归一化、迁移 | 任何视觉与真实交互 |
| 定点浏览器探针 | `npx tsx scripts/verify-browser.mjs`（`ONLY=<子串>` 只跑相关检查） | 真实 DOM 中的交互结果、几何、持久化 | 观感是否可接受 |
| 视觉验收 | 本节索引里的截图 + 人工逐张查看 | 布局、密度、遮挡、可读性 | 数据正确性 |

**截图不是交互证据，探针数字不是观感证据。** 两者都缺时不算验收通过。

## 4. 命名与留档约定

1. 每轮**一个**目录：`docs/sprint-<编号>-acceptance/`，不新增平行目录。
2. 文件名以轮次编号开头，末段写明视口（`1440` / `1024` / `375` / `320` / `430`）。
3. 失败与诊断截图**不进仓库**（`.gitignore` 已挡住 `test-results/`、`screenshots-tmp/`）；
   需要留证时贴在提交说明或 issue 里，不留在验收目录。
4. 同一状态下重复的图只留一张；跨轮复用的图留在原轮，不复制。
5. 单轮图片数量控制在 15 张以内；能用一个数字说清的，不再补一张图。
6. 删除图片时同步更新本索引与任何引用它的文档。

## 5. 关键回归入口

```bash
npm run typecheck     # 类型
npm test              # 813 个用例（含事务、迁移、归一化）
npm run build:pages   # 22 文件产物
npm run verify:version
npm run verify:deploy # 发布后与线上逐文件比对
```

浏览器专项**不要整体重跑**：用 `ONLY=<关键词>` 只跑受影响路径，完整
`verify-browser` 只在大范围改动时使用。
