## 1. 项目定位

**Character Studio** 是一个面向 OC（Original Character，原创角色）创作的**本地优先（Local First）**角色工作台。

它解决的是「一个人手里有几十上百个角色设定，需要一个统一的地方写、改、看、备份、导出」这件事：

- **写**：编辑器按六个模块组织设定（基础信息 / 外貌 / 性格 / 能力 / 背景故事 / AI Prompt）。
- **看**：预览页把设定渲染成一张可分享的展示稿。
- **管**：主页管理列表、搜索、筛选、排序、收藏、草稿、批量操作。
- **织**：关系网、世界观时间线、世界观管理把角色放进世界。
- **保**：JSON / ZIP / CSV 备份与恢复；PDF / JPG / PNG 展示导出。

目标用户：OC 创作者、小说 / 跑团 / 乙游 / 企划作者、需要整理 AI 绘图 Prompt 的创作者、希望离线管理角色资料的人。

### 产品原则（来自 `Developer Handbook.md`，本轮核查与代码一致）

| 原则 | 含义 |
| --- | --- |
| 本地优先 | 文字数据进 `localStorage`，头像二进制进 `IndexedDB`，不需要账号、不上传数据 |
| 不做服务器 | 当前阶段禁止引入后端、数据库、登录、远程 API |
| 读取即修复 | 损坏的存储值、未知类型、重复 id、悬空引用、成环层级都在读取时被安全处理，而不是让界面崩掉 |
| 破坏性操作有安全网 | 清空全部数据与导入文件都先写自动快照；删除角色会清理三个域中对它的引用 |
| 一次只动一件事 | Sprint 驱动；不顺手重构、不改目录、不改命名、不改数据结构 |
| 设置必须真的生效 | 「能配但没人读」的设置项应删除或标注「暂未应用」，不能静默失效 |

## 2. 用户流程

### 2.1 主流程：从新建到导出

```text
主页（Dashboard）
  │  角色列表 / 卡片视图 或 列表视图
  │  工具栏：搜索 → 筛选 → 视图切换 → 新建角色 → 更多
  ├─ 新建角色 ──► 编辑工作台（CharacterForm）
  │                 │  六个分节 + 左侧模块导航 + 完成度进度
  │                 │  操作栏：保存状态 · 随机生成角色 ｜ 返回 · 预览 · 更多 · 保存角色
  │                 │  Cmd/Ctrl+S 保存；自动保存草稿（可关）
  │                 └─ 保存 ──► 预览页（CharacterPreview, mode="browse"）
  ├─ 编辑 ──────► 编辑工作台 ──► 预览页（mode="editing"：返回编辑 / 保存草稿 / 删除角色 / 保存角色）
  ├─ 预览 ──────► 预览页（mode="browse"：编辑 / 收藏 / 导出 / 返回）
  └─ 更多操作 ──► 草稿箱 ｜ 收藏夹 ｜ 按世界观分组 ｜ 导入 ｜ 导出
```

### 2.2 三条二级工作区流程

```text
角色关系网（RelationshipGraph）
  新建关系（角色 A ⇄ 角色 B + 8 种关系类型 + 可选备注）
  → 画布：径向布局 / 滚轮缩放 / 拖拽平移 / 双指缩放 / 悬停高亮邻居
  → 画布栏：头像尺寸 · 名称尺寸 · 导出分辨率(1x/2x/3x) · JPG / PNG / PDF
  → 关系列表表格：关系 / 角色 / 另一方 / 备注 / 操作（删除）
  → 点击节点 ──► 该角色的预览页

世界观时间线（Timeline）
  新建事件（标题 + 日期 + 可选纪年 + 类型 + 地点 + 描述 + 涉及角色）
  → 按日期升序自动排序，按年份分组
  → 点击关联角色 ──► 该角色的预览页

世界观管理（WorldManager）
  新建条目（名称 + 分类 + 可选上级 + 简述 + 详情 + 标签 + 关联角色）
  → 按分类分组，支持层级（最多渲染 6 层）与折叠
  → 删除父级时子级脱离为顶层（不连带删除）
  → 点击关联角色 ──► 该角色的预览页
```

### 2.3 设置与数据入口

```text
顶栏：品牌标识（回到初始界面，清筛选）｜ 工作区切换 ｜ 主题（浅/深/跟随系统）
页脚（非主页）：About Character Studio ｜ 头像素材库 ｜ Settings
右下浮动栏：回到顶部 ｜ 滑到底部 ｜ （主页）新建角色 · 搜索筛选 ｜ （二级页）回到主页 ｜ （预览）编辑角色
```

## 3. 模块边界

页面之间**没有互相 import**（`App.tsx` 是唯一的调度者）。这条边界是本项目几乎所有重构能安全进行的前提。

| 层 | 目录 | 职责 | 不允许 |
| --- | --- | --- | --- |
| 外壳 | `src/App.tsx` | 页面状态、路由（`Page`）、主题、全局弹窗、浮动栏、跨页信号 | 不承载页面业务细节 |
| 页面 | `src/pages/` | 各自的界面与交互；通过 props 回调向上请求 | 不直接读写别的页面 |
| 组件 | `src/components/` | `AvatarDisplay`（头像显示唯一入口）、`Icon`（图标集）、`CharacterPicker`、`AiSettingsForm` | 不放业务写操作 |
| 状态域 | `src/hooks/` | 可复用的状态与副作用（保存、头像、分节、身份字段、图层、偏好、消息、媒体查询、键盘） | 不直接渲染 |
| 纯规则 | `src/pages/*/…ts`、`src/utils/` | 无 React 依赖的可测逻辑（图层声明、分节规则、裁剪几何、批量补丁、年龄、CSV、导入导出、颜色降级、懒加载恢复） | 不碰 DOM（`importExport` 的截图部分除外） |
| 存储 | `src/storage/` | 每个数据集一个模块，含键名、类型、归一化与读写 | 不在组件里散写 `localStorage` |
| 配置 | `src/config/` | 版本、主题令牌、开发者设置（单一真相源） | — |
| 类型 | `src/types/` | 跨页面共享的数据契约 | — |

### 三条被反复验证的边界规则

1. **`App.tsx` 拥有角色集合**。页面从不直接 `saveCharacters()`；它们调用 `onSave` / `onImport` / `onDelete` 等 props，由 App 写存储并同步状态。
2. **一个键只有一个所有者**。历史上有过「`character-studio.dashboard-prefs` 有 3 个写入方」的事故（视图模式被静默改回卡片）；现在 App 只做首次播种，Dashboard 是唯一所有者。Devil 在细节里：`pages/dashboard/layers.ts` 与 `storage/dashboardPrefs.ts` 的注释里都写着这条规则的来由。
3. **默认值是初始值，不是策略**。开发者设置只在**开发者本人改动它时**才应用到当前会话，不覆盖作者的偏好。

## 4. 核心功能清单（摘要）

完整清单（含入口、数据依赖、验证情况、遗留问题）见 **`docs/FEATURES.md`**。

- **角色管理**：CRUD、复制、收藏、置顶、草稿箱、删除撤销。
- **列表**：卡片视图（>30 个角色时按世界观分组、可折叠、吸顶）与列表视图（表格、逐行选择、状态列）。
- **搜索 / 筛选 / 排序**：关键词（角色名 / 职业 / 世界观 / 性格标签）、范围（全部 / 仅收藏 / 草稿箱）、世界观 / 性别 / 视觉风格筛选、四种排序。
- **批量**：批量编辑（可选字段）、批量收藏、批量复制、批量删除、批量导出。
- **编辑**：六个分节、模块导航与完成度、折叠记忆、跳到下一个未完成、随机生成角色、中文关键词生成、英文 Prompt 生成、创作辅助（随机灵感 / 追加 / 替换）、Emoji 与图片头像、裁剪、素材库选图、自动保存草稿。
- **预览**：双模式（浏览 / 编辑入口）、复制完整设定与两个 Prompt 字段、收藏切换、头像大图。
- **关系网 / 时间线 / 世界观**：见 2.2。
- **头像素材库**：浏览、统计、导入 / 导出 JSON、多选、批量删除、清理未使用、引用提示。
- **导入 / 导出**：单角色 JSON、全角色 JSON、完整备份 ZIP、CSV（含关系 / 世界观 / 时间线的全量表格）、头像素材 JSON、PDF / JPG / PNG。
- **通用**：浅色 / 深色 / 跟随系统、工作区导航、弹窗与菜单（Escape / 点击外部关闭）、Toast、快捷键、浮动栏、深链接（`/developer`）。

## 5. 总体架构

技术栈、路由、数据模型、数据流、持久化、导入导出与部署架构的完整说明见 **`docs/ARCHITECTURE.md`**。摘要：

| 方面 | 现状 |
| --- | --- |
| 技术栈 | TypeScript + React 18 + Vite 6；vitest 3 + happy-dom + fake-indexeddb 做测试；html2canvas + jsPDF 做截图导出（均动态 import） |
| 路由 | 无路由库。`Page` 是一个联合类型（7 个值），由 `App.tsx` 的 `useState` + History API 驱动；只有 `/developer` 有真实 URL |
| 状态 | 无状态管理库。组件本地 `useState` + 6 个自定义 hook + `App.tsx` 持有角色集合 |
| 持久化 | 文字进 `localStorage`（键总数 **21**，其中 1 个在 `sessionStorage`，见 `docs/ARCHITECTURE.md` 第 4 节）；头像二进制进 IndexedDB（库 `character-studio-assets`，版本 1） |
| 部署 | push `main` → GitHub Actions：`pnpm install --frozen-lockfile` → `typecheck` → `test` → `build:pages` → 部署 GitHub Pages；构建把 commit 与时间戳注入前端以便反查 |
| 规模 | `src/` 共 **26161 行**（`styles.css` 7177、`Dashboard.tsx` 3623、`CharacterForm.tsx` 3008、`importExport.ts` 1881、`App.tsx` 1671 为最大的五个文件） |
