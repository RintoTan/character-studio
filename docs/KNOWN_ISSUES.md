## 2. 不属于缺陷的产品边界

以下行为是明确的设计选择，不要作为 bug 上报：

| 现象 | 原因 |
| --- | --- |
| 换浏览器或清除站点数据后角色消失 | 数据只存在本地；没有云端，也没有跨设备同步 |
| 头像没有出现在角色库 JSON 里 | 该格式只承载文字；需要头像请用完整备份 ZIP 或单角色 JSON |
| CSV 导回后没有头像和关系 | CSV 是纯文字表格通道，不承载二进制与结构化关系 |
| 关系网首次只显示部分角色 | 默认核心视图避免一屏画满；文案已写明数量，可一键显示全部 |
| 导入提示「缺失引用」 | 导入包引用了不在包内的角色；系统不会伪造角色，需人工处理 |
| 删除父级世界观条目后子级仍在 | 设计为「脱离为顶层」，不是级联删除 |

## 4. 新增问题的写法

1. 先确认能在当前版本复现，并记录最小步骤。
2. 写清「观测到的现象」与「你认为的原因」是两件事；后者标为推断。
3. 标注优先级：P0 数据损坏 / P1 主要功能不可用 / P2 明显体验问题 / P3 细节。
4. 修复后不要直接删除条目：移到 `CHANGELOG.md` 对应版本，并在这里留一行指针。

### KI-31 卡片形态在按圆形间距保存的布局中会重叠（P2）

卡片节点宽 168、高 56，而既有布局的节点间距是为 60px 圆形准备的。切换到卡片形态时
（尤其是 40/100 人），相邻卡片会相互压住，导出中也可能在边缘被切。系统不会自动移动用户已保存的
坐标；缓解方式是切回头像/紧凑形态，或用「整理」重新排布。环形自动布局在没有保存坐标时已按卡片宽度计算间距。
