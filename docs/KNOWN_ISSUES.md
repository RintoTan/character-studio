| 字段 | 内容 |

| 验证证据 | 单测 `test/localDataReset.test.ts`（17 例，含注入 `localStorage.setItem` 抛错、`QuotaExceededError` 与其它错误名分别断言）；变异检验：移除阻断 → **4 条**失败，移除旧快照保留 → **1 条**失败。**真实浏览器**（`npm run verify:browser`）：「快照写入失败时不清空数据」→ 角色仍为 2 个、对话框显示「自动备份失败」；随后写入恢复 → 清空成功且快照保留 2 个角色 |

| 状态 | **已实现 / 待验收**。剩余两项都不是技术缺口，而是范围与验收事项 |

### KI-14　CSV 的关系行按角色名解析，重名时映射被导入角色覆盖　**P2**

| 字段 | 内容 |
| --- | --- |
| 发现方式 | 编写 `DEBUG_STRESS_TEST_PLAN.md` 时的代码审计（2026-10-15） |
| 复现条件 | 已有角色 A（名为「沈青梧」）→ 导出一份含关系行的 CSV → 把 CSV 里某行的角色名改成另一个同名角色，或直接导入一份**含同名新角色**的 CSV |
| 证据 | `src/utils/importExport.ts:669-679`：`nameToId` 先遍历 `existingCharacters` 建立姓名→id 映射（:670-674），**紧接着再用 `preparedCharacters`（本次导入的角色）覆盖同名键**（:675-679）。关系 / 时间线 / 世界观行随后靠这张表解析（:682-686） |
| 结论 | CSV 不携带角色 id，关系只能靠**姓名**建立。当导入的角色与现有角色同姓名的，映射指向的是**新导入的那个**，于是关系被连到新角色上；被连错的对象不会报错，也不会有提示 |
| 影响 | 静默的关系错连（`KI-12` 之外唯一一处会造成「数据看起来对、实际不对」的路径）。触发条件是重名，因此不需要恶意输入 |
| 建议方向 | 三选一：① 重名时不覆盖已有映射（保留先到者）并给出提示；② 解析前检测重名并把该行标记为「未解析」；③ 在 CSV 里增加可选的 id 列（会改变格式，需与迁移一起考虑） |
| 对应的验证用例 | `DEBUG_STRESS_TEST_PLAN.md` 的 `IO-IMPORT-014` |
| 已固化的证据（2026-10-15，Sprint 38） | `test/csvNameCollision.test.ts`，5 个用例，**全部复现当前行为**：① 导入角色与现有角色同名时，关系连到**新导入**的那个（不是名字原本指的那个）；② 同一文件内两个同名角色时，**后读到的那个**取得名字；③ 两个角色只在世界观上不同名相同时，世界观**不能**用于区分（映射只按名字）；④ 指向不存在角色的关系行被**静默丢弃**（这是既有语义）；⑤ 双方都命中现有角色时正常解析（无回归）。标着「缺陷 KI-14」的两条**描述的是缺陷而非契约**，修好时必须刻意改动它们 |
| 修复（Sprint 38.1，按 **DEC-38-03** 采用方案 A） | `src/utils/importExport.ts`：`nameToId` 只收「唯一指向一个角色」的名字（现有角色与本次导入角色一起统计），重名者进入 `ambiguousNames` 且**完全不参与解析**；新增 `countUnresolvedReferences()` 统计被跳过的引用，写入 `preview.unresolvedReferences`。旧语义是「最后一个写入该名字的角色胜出」 |
| 用户可见 | 导入预览的统计列表新增一行（仅在计数大于 0 时出现）：「未导入的关联：N 条 —— 角色重名 X 条、角色不存在 Y 条，无法确定指向，因此没有建立」；「冲突处理」说明区写明该规则。**未新增弹窗、未要求用户逐条选择、未改 CSV 列结构、未新增 ID 列** |
| 测试 | `test/csvNameCollision.test.ts` 由「描述缺陷」改写为**契约测试**（8 例）：同名导入角色不再夺走关系、同一文件内同名不二选一、跨世界观同名视为歧义、不存在的角色计入计数且其余数据照常导入、唯一名字正常连接、只一端歧义时不半连、时间线 / 世界观引用同样计数。变异检验：恢复「最后一个写入者胜出」→ **6 条**失败 |
| 状态 | **已实现 / 待验收**（含新增的用户可见文案，属交互决策） |

### KI-16　清空时会连带删掉**已有**的恢复快照　**P3**

| 字段 | 内容 |
| --- | --- |
| 发现方式 | Sprint 38 调查 KI-12 时的源码推演（写作 KI-12 的测试时注意到） |
| 源码证据 | `src/storage/backup.ts:22-24`：角色列表为空时 `createSnapshot` 直接返回 `null`；`src/storage/localDataReset.ts` 只在 `snapshot` 非空时回写。而 `localStorage.clear()` 已经把**上一份**快照删掉了 —— 于是「列表已空 + 存储里还有一份更早的快照」时，那份额外的副本被销毁且不重建 |
| 触发场景 | 有角色 → 导入或清空（写入快照）→ 把角色全部删掉（列表变为空）→ 再次点「清空本地数据」 |
| 影响 | 一个**仍可能救回上一版数据**的快照被销毁。丢失的是备份，不是当前数据；触发路径需要用户先清空列表 |
| 是否已验证 | **仅源码确认**，尚无测试。清单里没有它的用例 |
| 建议方向 | 列表为空时保留已有快照（`clear()` 之后把旧快照读出来再写回），或把「空列表」与「已有快照」分别处理 |
| 处理（Sprint 38.1） | `src/storage/localDataReset.ts` 在 `localStorage.clear()` **之前**先读出旧快照；列表为空（`attemptSnapshot` 返回 `empty`）时把它写回，结果对象因此多一个 `keptPrevious` 字段。列表非空时仍以新快照覆盖旧的 —— 恢复入口一直显示快照的时间与原因，所以保留旧副本不会引入「悄悄恢复过时数据」的新风险 |
| 测试 | 3 例：空列表时旧快照被写回（`keptPrevious: true`）、从未有过快照时为 `false`、有新数据时覆盖而非合并。变异检验：把 `keep` 改回只看新快照 → **1 条**失败 |
| 状态 | **已实现 / 待验收**（原判断是「不无提示地销毁唯一可用的恢复副本」，已按该原则修） |

### KI-17　角色删除入口之间的数据恢复能力不一致　**P2**

| 字段 | 内容 |

## 2. 已修复但值得记住的坑（防止再犯）

这些**不是**当前问题，但它们对应的机制仍然存在，改动相邻代码时应先读：

| # | 坑 | 机制 / 教训 |
| --- | --- | --- |
| 1 | 一个开关被三个地方写 | `isSearchPanelOpen` 曾有设置、复选框、roster-size effect 三个写入者 → 「进入页面关闭」不能作为可依赖的状态。**一个布尔量如果有多个写入者，它就不是约束** |
| 2 | React 的 `onWheel` 是 passive | 在 React 处理器里 `preventDefault()` 会被忽略；只有原生 `{passive:false}` 监听能拒绝滚动 |
| 3 | html2canvas 不能直接截 `<svg>` | 抛的是**裸字符串** `Unable to find element in cloned iframe`，不是 Error |
| 4 | html2canvas 只认 rgb/rgba/hsl/hex | `color-mix()` 的 computed value 是 `color(srgb …)`，遇到它**整张截图失败** |
| 5 | 合成事件不执行默认行为 | 合成 `WheelEvent` 不能用来测「页面会不会滚动」；必须用真实 `Input.dispatchMouseEvent` |
| 6 | 空转断言比失败更危险 | `!querySelector(...)` 与 `>=` 比较在行为没发生时也会通过；空 DOM 让所有关于它的断言为真 |
| 7 | 选择器权重 | `.relationship-table td`（类+元素）会盖过裸 `.relationship-col-actions` |
| 8 | `space-between` 配三个子元素 | 中间那个会被挤压；收进一个 wrapper 变成两个子元素才对齐 |
| 9 | `git commit -m` 里的反引号 | 被 zsh 当命令替换吞掉 → 用 `-F file` |
| 10 | 脏工作树改变构建产物 | 提交号会带 `-dirty` → 内容哈希变化 → `verify:deploy` 误报。必须**先提交、再重建、再校验** |
| 11 | 吸顶依赖 `body` 的 overflow | `overflow-y: auto` 会让 body 成为滚动容器，全站 `position: sticky` 静默失效 |
| 12 | 先验证观测点，再验证行为 | 拿已知的开/关两种状态各测一次观测点，确认它有区分度 |
| 13 | 改完 → 下一轮再验 | 同一条回复里的工具调用会并行执行，编辑与读取同批会读到旧内容 |
| 14 | 图标按钮没有文字 | 用文本查找必然找不到 → 用 `aria-label`，并加「空结果即报错」的前置断言 |
| 15 | 同一个事实存了两份就一定会漂移 | `package.json` 的 `version` 与应用版本（`src/config/version.ts` 的 `APP_VERSION`）各写一份，从 `0.1.0` / `1.0.0` 一路漂到与 `2.27.0` 不符（原 **KI-07**，2026-10-15 已统一为 `2.27.0`）。**同一事实有两个副本，迟早对不上；能收敛成一个来源的就不要留两个** |
| 16 | 文档的历史条目不能跟着改名 | `CHANGELOG` 里的旧条目描述的是**当时**的文件布局与数值（例如「31 个文件 / 360 个用例」）。文档落位调整后只更新现行文档与索引，**不动历史条目**，否则历史就不可信了 |
